# 全站内容审核与论文审核机制

本文档说明 Airalogy Scholar 的统一内容审核内核，以及普通论文如何使用该内核完成上传、审核、公开展示与重新审核。学位论文的业务字段和页面另见 `docs/degree-thesis-workflow.md`。

## 背景与设计动机

平台允许用户上传论文，但用户上传的元数据并不天然可靠，常见风险包括：

- 作者名拼写错误
- 机构归属错误
- 期刊、年份、DOI 填写错误
- 已公开论文被后续编辑后与原始记录不一致

如果未确认的数据直接进入公共检索、推荐、收藏和实验室主页展示链路，错误信息会被进一步传播，后续纠偏成本很高。因此平台采用“先上传、后审核、再公开”的治理策略。

## 核心原则

### 1. 上传不等于公开

- 用户可以上传任意论文
- 上传后论文先进入审核流程
- 只有审核通过后，论文才进入公共论文库、搜索结果和实验室代表论文展示

### 2. 公共展示只展示已确认内容

- 平台公共展示区默认只显示 `approved`
- 未审核或被驳回的论文不会进入公共检索与公开列表
- 已公开论文一旦被修改，会暂时退出公共展示，直到重新审核通过

### 3. 审核权来自平台角色、机构角色、实验室角色或机构组织审核流

- `platform_admin` 可审核所有论文
- 论文认领绑定 `institutionId` 时，对应机构的 `owner/admin` 可审核
- 论文认领绑定 `labId` 时，对应实验室的 `owner/admin` 也可审核
- 若论文认领绑定了 `reviewNodeId` 且机构配置了审核流，则当前审核步骤解析出的审核人也可审核
- v3 中每条论文认领都必须归属于一个机构

### 4. 机构成员论文绑定服务于展示和统计，不改变审核结论

- 机构后台可以把某个机构成员绑定为该机构论文库中某篇论文的某个作者
- 这类绑定是机构作用域内的运营数据，不是全平台作者身份合并
- 绑定不会让论文跳过审核，也不会让未审核论文直接进入公共展示
- 绑定后的成员论文列表和统计，仍应以该机构认领范围内的论文为边界

## 可见性规则

当前平台接口默认要求登录访问，因此这里的“公共展示”指平台面向所有登录用户的公开论文区。

- 上传者的“我的上传”
  - 可看到自己提交的全部 `paper_submissions` 及其对应审核状态
- 审核后台
  - 只能看到当前账号有权限审核范围内的 `paper_claims`
- 机构管理后台
  - 可看到该机构论文库中的作者绑定信息，以及基于绑定关系汇总的成员论文统计
- 公共论文库、搜索结果、实验室代表论文
  - 只显示 `approved`
- 论文详情页
  - `approved` 对所有登录用户可见
  - 非 `approved` 仅上传者、对应审核人和 `platform_admin` 可见

## 机构成员统计与展示口径

- `paperCount`
  - 统计该机构下，已经绑定到该成员的论文数
- `approvedPaperCount`
  - 统计该机构下，已经绑定到该成员且该机构认领状态为 `approved` 的论文数
- 成员加入机构后，不会自动继承其平台账号下的全部历史论文
- 只有被该机构显式绑定到成员的论文，才进入该机构成员视角下的展示和统计
- 同一篇论文可被多个机构分别认领、分别绑定成员、分别审核，这些关系彼此独立

### 5. 业务数据分离，审核内核统一

- 普通论文仍由 `papers` / `paper_claims` 表达 DOI、期刊、作者和机构认领
- 学位论文由 `degree_theses` / `degree_thesis_versions` 表达学号、培养单位、学位类别、版本和正文
- 两者都通过 `content_review_cases`、`content_review_step_instances` 和 `content_review_actions` 执行提交、逐级审核、退回、重提和留痕
- 可审范围、当前步骤、审核状态和操作历史均以统一审核表为准

## 状态机

### 统一审核状态

内核状态为：

- `draft`：尚未提交的可编辑版本
- `pending_review`：已提交，正在等待某一级审核
- `changes_requested`：任一级审核退回，等待提交人修改
- `approved`：全部步骤通过
- `archived`：已归档，不再接受提交

每次提交会将当时命中的 1–3 级流程和审核人快照到审核实例，后续修改流程不会篡改已发生的历史。

上传接口会创建：
  - 一条全局 `papers` 主记录（若 DOI 已存在则复用）
  - 一条 `paper_submissions`
  - 一条或一条被刷新的 `paper_claims`
  - 一条对应的 `content_review_cases` 及其步骤快照

审核真值不存在 `papers` 或 `paper_claims`；机构认领对应的 `content_review_cases` 是唯一状态来源。

## 状态流转规则

1. 创建未提交版本时，状态为 `draft`
2. 用户提交论文后，状态为 `pending_review`
3. 审核人确认无误后，状态改为 `approved`
4. 审核人要求修改时，状态改为 `changes_requested`，并必须填写审核意见
5. 上传者修改并重新提交后，状态回到 `pending_review`
6. 重新审核通过前，论文不出现在公共展示区
7. 同一篇论文可被多个机构分别认领并分别审核，这些认领状态互不影响

## 机构组织结构与审核流

当前平台已经支持在机构内部维护组织节点、关系边、岗位、任职以及审核流模板。

- 机构可以通过组织结构快照导入和维护内部结构
- 论文上传时可选传入 `review_node_id`
- 若命中机构组织审核流，系统会把审核步骤快照化到 `content_review_step_instances`
- 中间步骤通过后只推进到下一步，最后一步通过后才会把认领状态改为 `approved`
- 若任一步要求修改，则整条认领进入 `changes_requested`
- 平台管理员或机构 owner/admin 可通过 `PUT /v1/institutions/:slug/review-workflows/:contentType` 为 `paper` 和 `degree_thesis` 分别配置默认流程

组织结构的标准格式、字段约定和审核流解析规则，见 `docs/institution-org-structure.md`。

## 为什么不采用“先公开，再打未审核标签”

不采用该方案的原因是：

- 未审核论文仍会被搜索命中、收藏、引用和传播
- “未审核”标签只能提示风险，不能阻止错误数据污染平台
- 平台一旦定位为可信学术信息入口，就需要对公开数据设置质量门槛

因此，平台选择让审核成为公共展示的前置条件，而不是公开后的补充标记。

## 对接口与前端的约束

后端与前端应共同遵守以下约束：

- `GET /papers` 只返回 `approved`
- `GET /papers/search` 只返回 `approved`
- `GET /papers/review-queue` 只返回当前用户有审核权限范围内的论文认领
- `POST /papers/claims/:id/review` 仅处理待审核状态论文认领
- `POST /papers/create`、`PUT /papers/:id` 可选传入 `review_node_id`
- 论文被编辑后，需要按原状态进入重新审核流程，而不是继续保留公开状态
- 机构后台的作者绑定入口不应绕开成员权限校验；只有具备机构成员管理权限的账号可以绑定或解绑
- 机构成员页和机构论文库中的论文统计，应明确区分“绑定论文数”和“已审核论文数”
- 新的内容类型必须接入统一审核服务，不得在业务路由内自行修改审核步骤和审核历史
