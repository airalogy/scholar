# 学位论文专题与审核流程

[English](../en/degree-thesis-workflow.md) | 简体中文

Scholar 将学位论文作为独立内容域，但与普通论文共用全站审核内核。业务字段、版本和全文文件保持独立，提交、逐级审核、退回修改、重新提交和审计留痕由 `content_review_*` 表统一处理。

## 数据与版本

- `degree_theses` 保存机构、提交人、当前版本、已发布版本和发布时间。
- `degree_thesis_versions` 按行保存题目、作者、学号、培养单位、专业、学位类别、授予年份、导师、摘要、关键词、语言、可见范围、解密日期和 PDF 关联。
- 每次保存都创建不可变的新版本，审核操作明确关联当次版本。
- 已发布论文的新修订在审核中时，对外仍展示上一个已发布版本，不会提前替换正式内容。
- 普通访问者只看到已发布版本及“已发布”状态；未发布修订的状态、提交账号和审核进度不对外暴露。

### 标识符设计

- `id` 是数据库内部 UUID，用于外键和事务，不承载业务含义。
- `record_code` 是服务端生成的全局唯一、不可变展示编号，格式为“机构可读前缀 + `THS` + 96 位随机编码”，其中 `THS` 表示学位论文（thesis）。
- `institution_reference` 可选保留学校原系统的档案号，在同一机构内唯一，便于导入、对账和迁移；该字段仅向提交人、当前审核人及有权管理员返回，不在公开详情中展示。
- 学号、学位类别和授予年份都是可修正业务字段，不进入唯一编号；学号也不会出现在普通公开响应中。

## 审核与权限

- 提交人必须是该机构成员；机构内容管理员可代为编辑。
- 机构 owner/admin 默认可审核；普通成员可通过 `can_review_content` 成为显式审核员。该字段历史命名保留用于 API 兼容，实际已用于机构内容审核。
- 机构可分别为 `paper` 和 `degree_thesis` 配置 1–3 级默认审核流程。
- 一旦配置了分级流程，只有提交时被解析到当前步骤快照中的审核人可操作；通用审核权限不能越级，平台管理员保留应急处理能力。
- 任一级退回时必须填写意见；提交人修改新版本后可重新提交。
- 重新提交会重新解析当前流程，但旧审核动作保留当时的步骤顺序、名称、处理人、意见和时间快照。
- 只有最后一级通过才更新 `publishedVersionId`。
- 系统集成 JWT 不能访问提交、查看草稿或审核接口。

## 展示与文件安全

- 专题列表仅读取已审核的发布版本，支持题目/作者搜索及授予年份、培养单位、专业和学位类别筛选。
- PDF 只能通过服务端控制的 `thesis` 上传用途保存，对象前缀和保护策略不由浏览器指定。
- `public` 在解密后面向平台用户，`institution` 只面向同机构成员，`restricted` 只面向提交人和有权管理/审核的账号。
- 预览和下载使用短效访问链接，每次换取链接时都重新检查用户、机构、审核状态、可见范围和解密日期。

## 主要接口

- `GET /v1/theses` / `GET /v1/theses/facets`：已发布专题和筛选项。
- `GET /v1/theses/by-code/:recordCode`：使用稳定展示编号查询论文。
- `POST /v1/theses`、`PUT /v1/theses/:id`、`POST /v1/theses/:id/submit`：草稿、版本和提交。
- `GET /v1/theses/mine`：提交人工作区。
- `GET /v1/theses/review-queue`、`POST /v1/theses/:id/review`：待审队列与逐级审核。
- `GET/PUT /v1/institutions/:slug/review-workflows/:contentType`：机构默认审核流程。

全站审核的状态机、审核人解析和普通论文兼容投影见[论文审核流程](./paper-review-workflow.md)。
