# 人员与审核维护手册

本手册面向图书馆及机构管理员。入口为机构成员页的“人员与审核治理”，包含人员同步、人员与数据纠错、审核授权和审核路径试运行。

## 先明确分工

| 信息或操作 | 负责方 |
| --- | --- |
| 人员是否在职、在读，学号/工号，任职与导师关系 | 学校指定的权威系统 |
| 学校原始数据转换为 Scholar 标准格式 | 学校或部署方的私有适配程序 |
| 登录账号 | 本人首次 SSO 登录时创建并连接到人员档案 |
| 审核授权与流程规则 | 机构 owner 或平台管理员配置 |
| 具体材料审批 | 获得明确授权的审核人；系统管理员身份本身不是审核授权 |
| 临时数据更正 | 一位管理员提出，另一位有权管理员核验批准 |

学校认证成功不等于获得审核权。人员可以尚未登录，先拥有档案、论文绑定和审核授权。首次登录不需要重复创建人员。普通成员默认没有审核权。

姓名和邮箱不能作为自动合并人员的依据。同一人有多个编号时使用身份核验功能；不要通过删除旧人员、新建人员解决。撤销的编号保留归属，不能被同步程序重新分配。

## 上线顺序

1. 确定人员、学籍和组织信息的权威来源。一个人员档案由一个来源记录负责；多个上游系统应先在私有适配层完成权威归属与身份对齐，不能竞争覆盖同一人员。
2. 在“人员同步”建立来源。先用增量或关闭“缺失停用”的全量导入验证字段、人员数量和差异；校验不会修改正式人员，应用才会生效。
3. 对照学校记录核对人员与组织。保留独立的平台恢复管理员，完成完整权威快照后再决定是否开启“仅有效人员目录准入”。也可以保留默认 SSO 准入；升级不会替学校自动切换。
4. 在“审核授权”配置初审、部门、终审，以及必要的导师/负责人审核授权。部门授权需要对应单位任职；导师关系本身不会产生审核权。
5. 分别为普通论文、学位论文配置默认流程，最后阶段必须有图书馆终审。
6. 在“审核路径与试运行”发布条件规则。试运行典型学生、PI、多身份人员及跨部门作者，检查路径和缺失责任人。试运行只读取配置，不产生任务。
7. 用示例材料完成上传、参与范围核验、审批、退回和重提。确认所有业务入口遵守预期流程，再安排正式启用。

## 维护身份与关系

“人员与数据纠错”展示来源值、显示值、身份记录、任职历史和导师/负责人关系。身份可以并存，例如博士生兼科研助理。

身份代码固定为：本科生、硕士生、博士生、未细分层次研究生、博士后、教研人员、职员、PI、科研助理、访问人员、其他。它们是业务事实，不是任意标签，也不是访问权限。

源数据中的 `startsAt`、`endsAt` 表示有效期，空值表示未提供。有效区间包含起始、不包含结束。历史修订另记记录时间与被替代时间；系统不推断首次接入以前的真实组织历史。

日常操作：

- 新入校：同步人员及关系，首次 SSO 登录建立普通账号。
- 换学号：保留稳定人员标识，在核验后增加编号，不替换人员 UUID。
- 调岗：由源系统更新任职；旧授权不会因为新岗位出现自动恢复。
- 毕业或离职：同步状态，保留档案、论文及已完成审核；撤销高权限。返校后需重新授权。
- 部门改名：沿用原单位标识。合并为新组织：使用新标识，结束旧关系，确认新审核责任；不要把历史署名单位重写成当前部门。
- 导师变更：更新源关系。旧任务不能由新导师直接接手；核对影响后开始新轮次。

## 配置审核路径

规则代号保持稳定，每次保存生成新版本。高优先级先匹配；同一最高优先级存在多条匹配规则时暂停处理，不随机选择。

匹配条件包括材料类型、申请事项、作者身份、发表时单位。不同条件之间同时满足；每个条件的多个值匹配任一项；身份或单位空选表示不限。无匹配规则时使用机构默认流程。

条件针对**核实后的材料作者和发表时单位**，不是代上传人的身份。只要相关事项启用了身份/单位规则而参与范围尚未核实，就先进入异常任务。涉及身份条件但作者身份不完整时也暂停，不能用未知身份绕过审核。

导师/负责人阶段：有身份条件的规则，只对符合该身份条件的作者查找关系；没有身份条件时，对全部核实作者查找关系。多个有效关系均产生确认任务。关系及明确审核授权必须同时成立。

例如，博士生新材料可以配置“导师 → 全部发表时单位 → 图书馆终审”。PI 的材料可以匹配另一条规则。规则依据机构政策配置，不是平台对所有学校强制规定同一路径。多个身份/作者可能同时命中规则，须通过明确优先级或调整条件解决。

试运行使用**已经发布**的配置，不包含正在编辑但未保存的内容。选择全部相关人员及发表时单位，检查命中规则、候选审核人及缺失信息。实际审批仍重新检查权限、期限及自审限制；候选人列表不是审批保证。

## 日常审核与交接

上传者在“我的上传/我的申请”查看进展，审核人在“我的审核”处理任务。已收录 DOI 会在上传前提示，不应重复上传覆盖；使用详情页的更正申请。网络重试同一份未改动表单复用提交标识，不重复建立材料版本。

材料和流程在每轮提交时固定。处理异常前先核对当前材料版本：

- 作者或发表时单位不完整：补齐绑定并核实参与范围，重新开始审核。
- 无人可审、人员调岗：给合适人员授予明确权限；同一责任范围的角色任务可留痕转派。
- 导师关系、审核责任或规则需要改变：在后台填写原因，使用“按当前规则开始新轮次”。旧记录保留，旧审批不继承。
- 规则冲突：发布修正版本，再开始新轮次。不能通过转派把冲突任务改成普通审批任务。
- 审核人同时是提交人：不能进行自己的角色审批，安排其他合格人员；作者本人的作者确认与终审不同。
- 外部待办失败：重试通知。通知发送成功不代表审批完成，也不会自动发布。

## 数据有误怎么办

优先修复错误的来源：源系统事实错误找学校修正；转换错误修适配程序；Scholar 处理缺陷联系维护者修复后受控重放；本地授权配置错误在 Scholar 改正。

必要时可申请两种临时更正：

| 类型 | 限制 |
| --- | --- |
| 姓名显示更正 | 最多 30 天，保留源姓名，不改登录编号或账号归属 |
| 临时登录许可 | 最多 7 天，仅对错误的非活跃源状态提供准入例外；不绕过目录/任职要求，不解除人工暂停，不授予或恢复审核权限 |

申请和批准不能由同一管理员完成，也不能自己为自己的账号申请或批准更正。填写核验依据的引用，不填写密码、证件号码或无关个人资料。来源在审批前发生变化时需重新申请，不能沿用旧依据。

同步继续接收上游值。上游修好后更正自动结束；来源改成另一个冲突值时更正停止生效并保留记录。到期后临时登录权限立即失效，姓名显示由后台定时恢复，通常在 30 秒内；管理员也可随时撤销。正常权限仍按当前事实判断，失效不会删除账户或恢复旧授权。

此入口不支持直接修改编号归属、替换账号、合并人员、修改源任职或任意字段。这些操作必须经过对应核验或回源修复。

## 同步故障与交接清单

同步失败、超时或空数据不代表全体离职。不要为了“同步成功”而清空人员表。大规模停用需要检查完整性并人工确认；新格式接入见[人员同步协议](/zh/integration/personnel-sync)。

交接时至少确认：来源负责人、私有适配程序位置、最近同步时间、失败/待确认批次、有效审核授权、规则版本及试运行结果、未完成任务、临时更正及到期时间、恢复管理员、备份与升级负责人。实际名单、密钥和学校部署参数放在学校私有交接资料中。
