# 管理控制台

Scholar 在同一个产品中提供分层管理控制台。账号登录后，系统会从服务器获取当前权限，只显示已授权的工具和机构。

## 管理层级

### 平台控制台

平台管理员可以处理全局学科目录、用户反馈、跨机构审核队列及各机构的管理入口。

### 机构控制台

机构 owner 和 admin 可以管理机构内容、成员权限、学科映射、实验室和审核工作。普通 member 只会获得被单独授予的能力：

- `can_review_content`：处理所属机构的内容审核。
- `can_import_data`：向所属机构导入论文和学者数据。

这两项权限相互独立，也不会自动授予成员管理或系统凭证管理权限。`can_review_content` 只适用于旧审核流程；启用新流程后，owner 和平台管理员也须获得下述明确授权才能审批。

## 机构身份核验

机构 owner 和平台管理员可在机构“成员”页面处理**身份核验申请**及管理**机构身份编号**。普通 admin、数据导入和内容审核权限不包含此能力。

学校统一认证成功，但新学号或工号与平台已有账号冲突时，登录页提供“申请身份核验”。申请人填写原编号、变更说明并声明账号属于本人。提交申请不会获得原账号访问权；之后重新统一登录即可查看结果，临时核验会话过期不会删除申请。

请依据学校权威记录核实变更，明确选择原人员并记录核验依据，不能仅凭姓名或邮箱相同判定。可通过、驳回或要求补充信息。内部证据写在核验备注中，给申请人的反馈单独填写；不要索取密码或敏感身份证件附件。

通过后，新编号登录同一账号，原论文、档案和权限不变。管理员也可直接增加经核验的编号。撤销后的编号仍为原人员保留，恢复时须重新核验。管理员本人的附加编号必须由另一位有权管理员核验。

撤销会立即使通过该编号签发的新式 SSO 登录凭证失效；此功能上线前的旧会话和密码登录仍按原有效期工作，不等于账号全部退出登录。

## 人员与审核治理

机构 owner 和平台管理员从“成员”进入**人员与审核治理**。人员事实、登录准入和审核权分开配置：

1. 建立人员来源，先导入少量标准 JSON，检查变更前值、拟导入记录、错误及数量。校验不会修改人员，须另行确认应用。网页接受标准记录 **JSON 数组**；定时客户端接受系统接入指南中的 manifest。
2. 初始化时保留默认 SSO 准入。启用“仅有效人员目录准入”前，先应用完整权威快照并配置独立的平台恢复管理员；可额外要求有效任职。既有流程配置的审核角色须在新政策下仍有合格审核人，否则拒绝切换。仅手工创建人员档案不满足目录准入条件。未知 SSO 身份只能提交待核验申请，不能获得普通账号或登录会话。先修正权威人员记录，再批准准入；之后首次登录才创建普通 member 账号。
3. 单独授予图书馆初审、部门审核或图书馆终审。尚未登录的人员也可预先配置授权；部门审核要求在相应单位有效任职。每次审批重新校验期限与人员状态。学校认证、导入权限、同名或同邮箱均不产生审核权。
4. 分别配置普通论文、学位论文流程，例如“初审 → 全部本机构作者及全部发表时所属单位并行确认 → 图书馆终审”。每位作者均需确认，每个单位由一名当前有权代表处理；抄送不算审批。流程必须包含终审，申请人不得执行自己的角色审核任务。
5. 每个材料版本核实全部本机构作者绑定及**发表时单位范围**，不能用当前任职代替历史署名。范围或审核人缺失时进入异常队列，不能自动通过。修正参与范围后开始新轮次，原审批不沿用；作者确认不能委托另一个人。

人员同步不能设置角色或权限。增量中未出现的记录保留；只有明确启用缺失停用的完整权威全量快照，才会结束缺失人员及任职。大规模人员停用或审核授权丧失需要人工确认和理由。不同来源不能抢占同一人员；后续同步也不会解除人工停用。

离校或停用会即时阻止旧普通会话及受保护文件访问，撤销审核授权并移除高级成员权限；返校不自动恢复。结束的任职不会因重新出现而恢复原授权，其他有效兼职不受牵连。独立平台管理员保留恢复入口；原本公开的页面仍可匿名访问。

## 个人任务与变更申请

**我的审核**集中展示任务和申请。审批前查看固定版本的材料及 PDF。退回补正、驳回关闭、申请人主动撤回分别记录；重新提交开始新轮次，旧审批不能批准替换后的文件。

符合条件的已发布论文/学位论文详情可申请资料更正、本人论文作者绑定/解绑、全文限制、机构下架或恢复。批准并执行前不改变正式数据；机构下架不删除全局论文。恢复只适用于真正下架的已发布记录，不能恢复一个未通过的投稿。执行失败在管理端可见，应核查后重试；底层数据已变化时须提交新申请。

启用新审核流程后，重复上传同一论文不能替换已发布或归档的机构记录，应通过变更申请处理。待审核材料只允许原提交人重新提交。已发布普通论文的文件替换暂不属于第一版变更申请范围。

通知失败不会撤销审批，也不会触发发布。管理员可重试失败通知和对账任务状态；外部待办链接返回 Scholar，由当前有权的登录用户作出决定。

## 访问与安全

浏览器中的菜单和路由检查用于提供清晰的使用体验；真正的权限边界仍由每个服务器 API 独立校验。账号无权访问某项功能时，系统会显示权限受限页，不会展示其他机构的管理数据。
