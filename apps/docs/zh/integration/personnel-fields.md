# 人员与组织字段字典

供学校信息中心及对接供应商使用。先阅读[人员同步接口规范](/zh/integration/personnel-sync)了解鉴权、批次和更新流程。本页的“必填”针对**每条提交的记录**；增量同步不是任意字段的 PATCH。

## 通用约束

- 使用 UTF-8 JSON，业务字段使用区分大小写的 `camelCase`；记录和请求体不接受未定义字段。`external_id` 不能代替 `externalId`，枚举值如 `doctoral_student` 则必须保留原样。
- ID 均为字符串，保留前导零。来源 `externalId` 长度 1–100，至少含一个非空白字符；按来源和 `kind` 区分记录，不要求是 Scholar UUID。保持大小写、空格和编码稳定，不得把姓名、数组下标或每次随机生成的值作为人员键。
- `personExternalId`、`relatedPersonExternalId`、`unitExternalId`、`positionExternalId`、非空 `parentExternalId` 均为同一来源的 `externalId`，不是学工号或 Scholar UUID。引用记录须已存在，或在同一批中提供；记录可以跨页，服务端应用时处理依赖。
- `true/false` 必须为 JSON 布尔值；`"true"`、`"false"`、`0/1` 不符合布尔字段。外部系统需在私有适配层显式转换。
- 时间使用带时区 ISO 8601，例如 `2026-09-01T08:00:00+08:00` 或 `2026-09-01T00:00:00Z`，不要使用无时区的本地时间。未知时间传 `null`，不是空串、`"null"` 或 `0`。
- 有效区间为 `[startsAt, endsAt)`：起点包含、终点不包含；两者都有值时，结束时间必须严格晚于开始时间。`active` 记录仍受时间范围限制；`ended` 表示已终止，不因日期为空而重新生效。
- 仅按业务需要提供字段。不要传密码、令牌、身份证号码、任意学校专有列、`userId`、`scholarId`、管理员角色、审核权限或 `can_import_data`。

## 记录字段

### person

人员事实，可先于首次登录存在。`schemaVersion` 1、2 均支持。

| 字段 | 必填 | 类型与约束 | 含义 |
| --- | --- | --- | --- |
| `kind` | 是 | 字符串，固定 `person` | 记录类型 |
| `externalId` | 是 | 字符串，1–100 | 来源中的永久人员键；换学号或工号不换此键 |
| `name` | 是 | 字符串，1–100 | 显示姓名，提交前清洗空白；不用于自动合并 |
| `identifiers` | 是 | 字符串数组，1–20 个唯一值；每值 1–100 | 已核实属于本人的机构编号，例如 `["STU-0001", "EMP-0002"]` |
| `email` | 否 | 邮箱格式字符串，最多 100，或 `null` | 人员联系邮箱；不作为账号归并依据，不改写登录账号邮箱 |
| `category` | 是 | 枚举，见下文 | 兼容的粗粒度人员类别 |
| `status` | 是 | 枚举，见下文 | 人员生命周期状态，不是审核授权 |

`category`：`staff`（教职工）、`undergraduate`（本科生）、`postgraduate`（研究生）、`visitor`（访问人员）、`other`（其他）、`unknown`（尚不明确）。博士生等细分身份用 `identity`；不要把 `doctoral_student` 填入 `category`。

`status`：`active`（在校/在职）、`departed`（离校/离职）、`graduated`（毕业）、`suspended`（源系统暂停）。不存在 `deleted` 状态。非 active 状态会影响准入并撤销相应权限，恢复 active 不自动恢复旧授权；人工暂停仍独立生效。

编号比较会去掉首尾空白并忽略大小写。数组中规范化后相同的编号会冲突；不要依赖大小写区分两个人。新人员以第一个编号初始化规范编号；后续增加、重排编号不替换既有规范编号。省略旧编号不会撤销旧编号，撤销需管理员独立核验；已撤销编号不能靠再次同步自动恢复。

### unit

组织单位，例如学院、部门或课题组。版本 1、2 均支持。

| 字段 | 必填 | 类型与约束 | 含义 |
| --- | --- | --- | --- |
| `kind` | 是 | 字符串，固定 `unit` | 记录类型 |
| `externalId` | 是 | 字符串，1–100 | 稳定单位键；单纯改名不换键 |
| `name` | 是 | 字符串，1–200 | 单位名称 |
| `active` | 是 | 布尔值 | 是否有效；不是人员状态字符串 |
| `parentExternalId` | 否 | 字符串，1–100，或 `null` | 同源父单位；省略保留旧关系，`null` 移除父关系 |

父单位不能是自己，不能形成循环，也不能借同步覆盖其他来源或手工维护的父关系。机构重组不应重写论文发表时的历史单位。

### position

单位中的岗位，可关联多条人员任职。版本 1、2 均支持。

| 字段 | 必填 | 类型与约束 | 含义 |
| --- | --- | --- | --- |
| `kind` | 是 | 字符串，固定 `position` | 记录类型 |
| `externalId` | 是 | 字符串，1–100 | 稳定岗位键 |
| `unitExternalId` | 是 | 字符串，1–100 | 同源所属单位键 |
| `name` | 是 | 字符串，1–100 | 岗位名称 |
| `active` | 是 | 布尔值 | 岗位是否有效 |

岗位名称如“院长”“PI”本身不授予审核权。岗位停用或转移到其他单位会移除相应任职的旧审核授权依据。

### appointment

连接人员与岗位，一人可以有多条任职。版本 1、2 均支持。

| 字段 | 必填 | 类型与约束 | 含义 |
| --- | --- | --- | --- |
| `kind` | 是 | 字符串，固定 `appointment` | 记录类型 |
| `externalId` | 是 | 字符串，1–100 | 稳定任职键，不可转给另一人 |
| `personExternalId` | 是 | 字符串，1–100 | 同源人员键 |
| `positionExternalId` | 是 | 字符串，1–100 | 同源岗位键 |
| `status` | 是 | `active` 或 `ended` | 任职状态 |
| `startsAt` | 是 | 带时区时间字符串或 `null` | 生效开始时间 |
| `endsAt` | 是 | 带时区时间字符串或 `null` | 生效结束时间 |

调岗建议结束旧任职，并为新任职使用新键，以保留业务关系。系统保留观测到的任职历史；重新任职不自动恢复旧审核授权。

### identity

精确的人员身份事实，一人可同时拥有多条；仅版本 2 支持。

| 字段 | 必填 | 类型与约束 | 含义 |
| --- | --- | --- | --- |
| `kind` | 是 | 字符串，固定 `identity` | 记录类型 |
| `externalId` | 是 | 字符串，1–100 | 稳定身份记录键，不可转给另一人 |
| `personExternalId` | 是 | 字符串，1–100 | 同源人员键 |
| `code` | 是 | 枚举，见下文 | 身份代码，不是权限标签 |
| `status` | 是 | `active` 或 `ended` | 身份状态 |
| `startsAt` | 是 | 带时区时间字符串或 `null` | 生效开始时间 |
| `endsAt` | 是 | 带时区时间字符串或 `null` | 生效结束时间 |

`code`：`undergraduate`、`masters_student`、`doctoral_student`、`postgraduate`、`postdoc`、`faculty`、`staff`、`pi`、`research_assistant`、`visitor`、`other`。

例如同一人可同时是 `doctoral_student` 和 `research_assistant`，分别用两条记录表示。不明确身份时先核查，不根据姓名、岗位名称或粗粒度 `category` 猜测；身份路由缺少必要事实时会进入待核查，而不是静默跳过。

### relationship

人员间的导师/负责人关系；仅版本 2 支持。

| 字段 | 必填 | 类型与约束 | 含义 |
| --- | --- | --- | --- |
| `kind` | 是 | 字符串，固定 `relationship` | 记录类型 |
| `externalId` | 是 | 字符串，1–100 | 稳定关系记录键，不可转移关系主体 |
| `personExternalId` | 是 | 字符串，1–100 | 被指导或被负责的人员键，例如学生 |
| `relatedPersonExternalId` | 是 | 字符串，1–100 | 导师/负责人键；须与主体不同 |
| `relationship` | 是 | `supervisor` 或 `responsible` | 导师或其他负责人关系 |
| `status` | 是 | `active` 或 `ended` | 关系状态 |
| `startsAt` | 是 | 带时区时间字符串或 `null` | 生效开始时间 |
| `endsAt` | 是 | 带时区时间字符串或 `null` | 生效结束时间 |

一个人有多名导师时，可使用多个稳定关系键。换导师会形成新版本；旧审核轮次不自动换人。关系事实不等于审核授权，仍需独立的导师/负责人审核授权。

## 省略、空值和结束关系

| 输入 | 现有记录的含义 |
| --- | --- |
| 增量批次中不含某条记录 | 不修改该记录 |
| 记录省略必填字段 | 非法；增量并不免除必填要求 |
| `email` 省略 / `null` | 保留已有人员邮箱 / 清空人员邮箱 |
| `parentExternalId` 省略 / `null` | 保留旧父关系 / 移除父关系 |
| `startsAt` 或 `endsAt` 为 `null` | 写入未知/未指定时间；不是“保持旧值” |
| `identifiers: []` 或 `null` | 非法；至少一个已核实编号 |
| 从 `identifiers` 中省略旧编号 | 保留旧编号；不能用此操作撤销或转移编号 |
| `active: false` | 明确停用单位或岗位，不等于未提供 |
| 人员非 active 状态、关系 `ended` | 保留记录和历史，不硬删除 |
| 完整全量批次缺少记录 | 只有开启权威缺失停用时才按协议停用；请先预览并确认 |

不要直接把全表空白统一替换为 `null`：字段允许空值的范围和含义不同。学校专有字段不应直接加入上述对象，应在私有适配层处理或经双方确认扩展标准协议。
